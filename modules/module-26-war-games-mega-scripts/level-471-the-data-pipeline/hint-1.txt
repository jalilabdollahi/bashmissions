Treat each file as a small batch that moves through five stations: ingest (clean the bytes, check the header, recognise a re-delivery), validate, deduplicate, transform, load. Keep two memories in the scratch directory that are updated as the run proceeds: the order ids already loaded and the files already processed. That way a duplicate in the same run, a duplicate from yesterday and a file delivered twice are all caught by the same lookups, and `--dry-run` can behave exactly like the real run without writing anything.
