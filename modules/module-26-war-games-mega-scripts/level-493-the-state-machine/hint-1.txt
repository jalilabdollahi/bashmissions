A state machine is a lookup table: given (current state, event), what is the next state, and what has to be true for the move? Load the definition once into associative arrays keyed by "FROM|EVENT". Everything else is a view of that table: `validate` walks it looking for mistakes in the design, `show` reads one ticket and lists the events that leave its state, and `fire` runs the checks in a strict order (is the event allowed here? may this role do it? is the required data present?) before changing anything. Parse the machine file first and report all bad lines before doing the real work.
