Model the bus as an append-only log plus one bookmark per reader. Publishing adds a numbered file to the spool and never changes it. Every subscriber has a cursor, the highest message number it is finished with, and dispatching means "for each subscriber, walk the messages after its cursor in order, deliver the ones that match, and move the cursor". Because each reader has its own cursor, a slow or broken one cannot hold back the others, and a new reader can start at the end of the log. Keep the failure bookkeeping (how many attempts for which message) in a small file per subscriber, so it survives between dispatch runs.
