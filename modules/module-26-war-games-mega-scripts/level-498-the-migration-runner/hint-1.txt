Two sources of truth have to agree: the folder says which migrations exist and what they contain right now, the ledger says which ones were applied and what they contained at that time. Every command is a comparison of the two. Compute, for each id, a state: applied (both agree), MODIFIED (same id, different fingerprint), MISSING (in the ledger only), pending (on disk only). `up` first looks for states that make it unsafe to continue, then runs the pending ones in id order and writes to the ledger after each success. Never write the ledger before the work is done, and never run anything after a failure.
