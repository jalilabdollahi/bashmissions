Build one rule engine and give it three faces. The core is a function `evaluate ID` that answers "does this rule hold right now?" and, if not, leaves a message saying why. `check` simply prints the answer. `enforce` adds a second function that changes the system and then calls `evaluate` again, because a fix you have not verified is a hope. `--dry-run` runs everything except the change. Waivers are the first thing the main loop looks at: a valid waiver short-circuits the rule, an expired one is mentioned and ignored. Parse and validate the whole rules file before doing anything.
