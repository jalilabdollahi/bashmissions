# Debrief: Dry-Run Mode

A dry run is a rehearsal: the script goes through all its logic, takes all its
decisions, and instead of changing the world it tells you what it would have
changed. It is the safest debugging tool for destructive scripts, because you
can run it on a live server, as often as you like, and read the plan.

The pattern is a single choke point. Every command with a side effect goes
through one function, `run`, and the function consults a flag. This has a
useful property: the dry-run output is generated by the same code path as the
real run, so it cannot drift from reality. The alternative, a second block of
`echo` lines, is a copy that goes out of date.

Two Bash details make it solid. `"$@"` re-runs a command exactly, preserving
every argument boundary. And `printf ' %q' "$@"` renders those same boundaries
for human eyes: `%q` escapes spaces and special characters so the line can be
pasted into a terminal and do what the script would have done. A plain `echo $*`
would hide the difference between one argument with a space and two arguments.

Mind the limits: the dry run only describes commands that go through `run`.
Reads, which are harmless, normally run for real so that later decisions have
real data to look at.

You will see `--dry-run`, `-n` or `--check` in `rsync`, `make`, `apt` and
Ansible, with the same promise.

Going further: if you can describe the expected result, a script can check it
itself. Next up are assertions.
